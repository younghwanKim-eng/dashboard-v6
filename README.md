# 중장비 전도 예방 대시보드 (v6 — 관리자 + 모바일 근로자)

VSCode + Streamlit 에서 바로 돌아가는 로컬 대시보드입니다.
외부 DB 연결 없이 2018.xls + equipment_slope_data.csv + 로컬 JSON 만으로 완전 동작합니다.

v6부터 **관리자 대시보드(PC 가로형)** 와 **현장 근로자용 모바일 웹 앱(세로형)** 이 한 코드에서 역할별로 분기됩니다.

## 폴더 구조

```
dashboard_v6/
├─ app.py              # 엔트리 포인트 (로그인 + 역할 라우팅 + 관리자 대시보드)
├─ worker_app.py       # 모바일 근로자 UI (하단 탭 4개)
├─ worker_styles.py    # 모바일 전용 CSS (반응형·세로 1열·터치 44px·safe-area)
├─ worker_data.py      # 작업/공지/문의 JSON 영속 + gsk gmail send_email 발송
├─ data/
│   ├─ 2018.xls                   # 2018~2020 날씨 (6개 지점)
│   ├─ equipment_slope_data.csv   # 건설장비 지반 경사도·전도 한계
│   ├─ assignments.json           # 근로자별 작업 배정 (상태·이력 포함)
│   ├─ announcements.json         # 관리자 공지 (critical / info)
│   └─ inquiries.json             # (자동 생성) 근로자 → 관리자 문의 로그
├─ requirements.txt
└─ README.md
```

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

접속 후 URL 뒤에 쿼리파라미터로 모드를 수동 전환할 수 있습니다.

| URL | 결과 |
|---|---|
| `?m=auto` (기본) | 로그인한 계정의 역할에 따라 자동 분기 |
| `?m=worker` | 모바일 근로자 앱으로 강제 전환 (관리자가 모바일 UI를 확인할 때 유용) |
| `?m=admin` | 관리자 대시보드 — admin 역할이 아니면 차단되고 모바일로 되돌림 |

## 1) 관리자 대시보드 (PC)

로그인 후 `admin01` 로 접속하면 기존 가로형 대시보드가 열립니다. 탭 구성:

1. **👤 로그인 정보 화면** — 사용자/시간/장비/소속 + 날씨 매칭 결과
2. **📊 대시보드 화면** — 기상 요약, 지반 기울기 분석, 종합 전도 위험도,
   그리고 **📣 금일 작업 가능 여부 판정** (초록 / 노랑 / 빨강)
3. **📚 장비 전도 한계표** — equipment_slope_data.csv 전체 (8종)
4. **✅ 작업 전 안전 점검 체크리스트** — 10개 핵심 점검 항목

### 금일 작업 가능 여부 판정 로직
- 종합 위험도 **< 30**: ✅ **작업 가능**
- 종합 위험도 **30~59**: ⚠️ **조건부 작업 가능 (주의)**
- 종합 위험도 **≥ 60**: 🛑 **작업 중지 권고**
- **법정 하드 룰 오버라이드**
  - 이동식 크레인 + 최대 풍속 ≥ 18 m/s → 작업 중지
  - 스카이(고소작업차) + 최대 풍속 ≥ 10 m/s → 작업 중지

### 안전 점검 판정 로직
- 10개 항목(각 1점, 만점 10점) — 양호(≥90%) ✅ / 보통(60~89%) ⚠️ / 위험(<60%) 🛑
- 풍속·경사 한계는 로그인한 사용자의 장비·허용 작업 경사 각도로 라벨이 자동 조정
- 제출 시 `st.session_state['safety_check_log']` 에 누적

## 2) 모바일 근로자 앱 (스마트폰 세로)

로그인 후 **worker 역할** 로 접속하면 자동으로 모바일 레이아웃이 열립니다
(사이드바·메뉴 숨김, 최대 폭 480px 중앙, 하단 고정 탭, 터치영역 ≥44px, iOS 자동줌 방지,
safe-area-inset 반영).

### 하단 탭 4개

| 탭 | 하는 일 |
|---|---|
| **🏠 홈** | 오늘 날짜 · 작업 가능 여부 큰 배너 (색+텍스트 동시) · 핵심 수치 3개(최대 풍속·강수량·허용 경사) · 공지 상단 2건 · 오늘의 작업 요약 |
| **📋 내 업무** | 본인에게 배정된 작업만 표시(함수 레벨 필터). 카드 → 상세 → **상태 변경 버튼**. 상태 전이: 대기 → 진행 중 ⇄ 일시정지 → 검토 요청(완료 보고) → 완료. 완료 보고는 되돌릴 수 없어 **확인 모달** 노출 |
| **✅ 안전 점검** | 관리자 앱과 동일한 10개 항목을 **세로 폼**으로 표시. 라벨은 사용자 장비 기준으로 자동 보정(풍속 한계, 허용 경사). 결과·이력은 세션에 누적 |
| **👤 내 정보** | 프로필 조회(수정은 관리자만) + **관리자에게 문의 보내기** (`gsk gmail send_email` 로 `leelyanglae@naver.com` 실제 발송, 메일 실패 시에도 로컬 JSON에 저장) + 내 문의 이력 + 로그아웃 |

### 권한 분리 (지침 §5)
- `worker_data.py` 의 `list_assignments / get_assignment / update_status` 는 **반드시 user id 로 필터**.
  다른 근로자의 작업·개인정보·관리자 통계·권한 설정은 노출되지 않음.
- 비관리자 계정이 `?m=admin` 으로 접근하면 경고 후 모바일 홈으로 복귀.

### 데이터 영속 (JSON 파일)
- `data/assignments.json` — 작업 배정. 상태 변경 시 history 배열에 (`at`, `to`) 추가.
- `data/announcements.json` — 공지 (level=critical/info).
- `data/inquiries.json` — 자동 생성. 근로자 문의 로그.
- 저장은 `tmp → os.replace` 원자적 쓰기.

### 메일 발송 — gsk CLI
문의는 다음 명령으로 발송됩니다:
```bash
gsk gmail send_email \
  --recipient leelyanglae@naver.com \
  --subject "[현장 문의] 속초 · 김현장 · 안전장비 교체 요청" \
  --body "..."
```
Streamlit 런타임에 Gmail 연결이 없거나 CLI 미설치면 메일 발송은 실패하지만
문의 자체는 `data/inquiries.json` 에 저장되고 사용자에게 사유가 안내됩니다.

### 작업 상태 전이표

| 현재 | 허용되는 다음 상태 |
|---|---|
| 대기 (`pending`) | 진행 중 |
| 진행 중 (`in_progress`) | 일시정지 / 검토 요청 |
| 일시정지 (`paused`) | 진행 중 |
| 검토 요청 (`review_requested`) | — (관리자 승인 대기, 근로자는 변경 불가) |
| 완료 (`done`) | — (종료) |
